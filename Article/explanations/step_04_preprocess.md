# step_04_preprocess.py の解説

## このコードの役割

質量分析から得られた**生のタンパク質定量データを統計解析に適した形に変換**するスクリプトです。データサイエンスにおける「データクリーニング」の重要なステップで、後続の統計解析や機械学習の精度を大きく左右します。

## 全体フロー

```
生定量データ → ログ変換 → 欠損値フィルタリング → 欠損値補完 → 統計解析用データ
    ↑              ↓              ↓              ↓              ↓
（歪んだ分布）   （正規分布化）    （品質管理）     （完全データ）   （t検定・PCA等）
```

| | ファイル | 内容 |
|-|---------|------|
| **入力** | `results/protein_matrix_from_sage.csv` | Sage解析結果（タンパク質×サンプル行列） |
| **入力** | `data/raw/Table_S2_*.xlsx` | 論文補足データ（比較用） |
| **出力** | `results/preprocessed_data.csv` | 前処理済みデータ（Log2変換・補完済み） |
| **出力** | `results/sample_info.csv` | サンプル情報（Normal/Tumor分類） |

**所要時間の目安**: 10-15分（データサイズとCPU性能による）

## なぜ前処理が必要なのか？

### 1. 値の分布問題
質量分析の生データは極端に歪んだ分布を持ちます：

```
生データ例:
タンパクA: [1,000, 2,000, 50,000, 100,000, ...]
タンパクB: [500,000,000, 800,000,000, ...]

Log2変換後:
タンパクA: [10.0, 11.0, 15.6, 16.6, ...]
タンパクB: [29.9, 29.6, ...]
```

### 2. 統計手法の前提条件
多くの統計手法（t検定、ANOVA等）は**正規分布**を前提としています。Log変換により正規分布に近づけることで、統計的検定が適切に機能します。

### 3. 欠損値問題
質量分析では「検出限界以下」のタンパク質が欠損値として記録されます。これらを適切に処理しないと、統計解析が不可能になります。

### セクション2: Log2変換

```python
if not is_log_transformed(df):
    print("データがLog2変換されていません。変換を実行します...")
    df = np.log2(df + 1)  # +1 は 0 値への対応
else:
    print("データは既にLog2変換済みです。")
```

**目的**: 値の分布を正規分布に近づける

**引数の意味**:
- `df + 1`: ゼロ値のログ変換問題を回避（log2(0) = -∞になるため）
- `is_log_transformed()`: 既にLog変換済みかを判定（中央値で判定）

**変換の効果**:
```
変換前: [1, 10, 100, 1000]     → 非常に歪んだ分布
変換後: [1.0, 3.7, 6.6, 10.0] → より均等な分布
```

**目的**: 信頼性の低いタンパク質（ほとんど検出されない）を除外

**フィルタリング基準**:
- **Normal群**または**Tumor群**のどちらかで、70%以上のサンプルで検出されたタンパク質のみ残す
- 例：Normal群16サンプル中、12サンプル以上で検出されている

**生物学的根拠**:
```
タンパクA: Normal群で2/16検出、Tumor群で1/16検出 → 除外（信頼性低）
タンパクB: Normal群で15/16検出、Tumor群で12/16検出 → 保持（信頼性高）
```

### セクション4: 欠損値補完（Perseus互換）

```python
IMPUTATION_DOWNSHIFT = 2.4  # 有効値の平均から2.4SD下に補完値の中心を置く
IMPUTATION_WIDTH = 0.3      # 元のSDの30%の幅で補完値をばらつかせる
```

**目的**: 「検出されなかった」タンパク質に適切な推定値を割り当て

**補完の仕組み**:

| パラメータ | 値 | 意味 |
|-----------|---|------|
| `downshift` | 2.4 | 検出値より2.4SD低い値として補完 |
| `width` | 0.3 | 補完値にも自然なばらつきを与える |

**補完値の計算例**:
```
あるサンプルの有効値: 平均=20, SD=2
→ 補完値の中心 = 20 - 2.4×2 = 15.2
→ 補完値の範囲 = 15.2 ± (2×0.3) = 14.6〜15.8
```

**なぜこの方法か**:
- **生物学的妥当性**: 検出されない＝存在量が少ない、という仮定
- **Perseus互換**: 論文で使用された前処理と同等の結果が得られる
- **統計的適切性**: ランダムな補完により分散構造を保持

## 【深掘り】 欠損値とは何か？

- **ひとことで**: 測定装置の検出限界以下で「存在するが測定できない」データ
- **3種類の欠損**:
  1. **MCAR** (Missing Completely At Random): 完全にランダムな欠損
  2. **MAR** (Missing At Random): 他の変数で説明可能な欠損
  3. **MNAR** (Missing Not At Random): 欠損自体に意味がある ← **プロテオミクスはこれ**
- **プロテオミクス特有の問題**: 低発現タンパク質の欠損は生物学的意味を持つ
- **対応戦略**: 単純削除ではなく、生物学的仮定に基づく補完が必要

## 【深掘り】 Log変換はなぜ必要？

- **ひとことで**: 乗法的変化を加法的変化に変換し、統計手法を適用可能にする
- **生物学的背景**: タンパク質発現量は「2倍」「3倍」のような比率で変化
- **数学的効果**:
  ```
  元データ: [1, 2, 4, 8] → 比率変化
  Log2変換: [0, 1, 2, 3] → 等間隔変化
  ```
- **統計的利点**:
  - 正規分布への近似
  - 分散の安定化
  - 外れ値の影響軽減

## よくある質問

**Q: 「Log2変換済み」の判定はどのように行っているの？**
A:
```python
def is_log_transformed(df):
    median_val = df.median().median()
    return median_val < 100  # Log2値は通常50以下
```
中央値が100未満ならLog変換済みと判定します。生データは通常10^4以上なので区別できます。

**Q: 70%という閾値の根拠は？**
A: Toyota et al. 論文のPerseus設定に準拠しています。生物学的には「群の大部分で検出される」という意味で、統計的検定に十分な検出力を保つための基準です。

**Q: なぜ +1 してからLog変換するの？**
A: ゼロ値のLog変換を防ぐためです：
```
log2(0) = -∞  # 計算不可
log2(1) = 0   # 適切な値
```
この +1 は「pseudocount」と呼ばれる一般的な手法です。

**Q: 補完値が実際の測定値より大きくなることはありますか？**
A: 設計上ありません。`downshift=2.4`により補完値は必ず検出値より小さくなります。これは「検出されない＝少ない」という生物学的仮定に基づいています。

**Q: Perseusと完全に同じ結果になりますか？**
A: 乱数シードが同じなら同一結果になります。異なる場合でも統計的性質（平均、分散）は同等です。

**Q: 自分のデータに適用する場合、パラメータを変更すべき？**
A:
- **実験系が同じ**: パラメータそのまま使用推奨
- **異なる生物種**: VALID_VALUE_RATIOを種に応じて調整
- **異なる測定装置**: IMPUTATION_PAラメータの再調整を検討
